\section{Working Modes}
Roo Code uses specialized personas to optimize token usage and task accuracy.

\includegraphics{./include/graphics/roocode/RooCodeModes.png}

\begin{itemize}
   \item \textbf{Architect:}
      \begin{itemize}
         \item \textbf{Goal:} Planning and high-level design.
         \item \textbf{Behavior:} Proposes solutions and analyzes code without
            making changes.
      \end{itemize}
   \item \textbf{Code:}
      \begin{itemize}
         \item \textbf{Goal:} Full implementation.
         \item \textbf{Behavior:} Has full write-access to create features,
            refactor code, and update the workspace.
      \end{itemize}
   \item \textbf{Debug:}
      \begin{itemize}
         \item \textbf{Goal:} Bug hunting and fixing.
         \item \textbf{Behavior:} Specifically designed to analyze logs,
            terminal errors, and fix broken test scripts.
      \end{itemize}
   \item \textbf{Orchestrator:}
      \begin{itemize}
         \item \textbf{Goal:} Complex task management.
         \item \textbf{Behavior:} Breaks down large objectives into smaller
            sub-tasks for execution.
      \end{itemize}
   \item \textbf{Ask:}
      \begin{itemize}
         \item \textbf{Goal:} Knowledge retrieval.
         \item \textbf{Behavior:} Acts as a read-only consultant to explain
            logic or query documentation.
      \end{itemize}
\end{itemize}

\section{Configuration Profile}

Roo Code's \textbf{API Configuration Profiles} allow you to save and manage
multiple named sets of LLM settings — each with its own provider, model,
API key, and temperature.
Instead of manually reconfiguring the extension every time you switch tasks,
you simply switch profiles with a single click.

\begin{boxhint}{Why use profiles?}
Different tasks benefit from different models:
\begin{itemize}
   \item A \textbf{complex refactoring} task needs a powerful reasoning model
      (e.g., Claude Sonnet — latest).
   \item A \textbf{quick documentation update} may work well with a faster,
      cheaper mid-tier model (e.g., DeepSeek-V3).
   \item A \textbf{private, offline} task is best served by a local model
      via Ollama.
\end{itemize}
Profiles let you pre-configure all these combinations and switch between
them instantly.
\end{boxhint}

\subsection{Creating a New Profile}

\begin{enumerate}
   \item Click the \textbf{Roo Code icon} in the Activity Bar to open the panel.
   \item Click the \textbf{Settings (gear icon)} at the top of the Roo Code panel.
   \item In the settings panel, locate the \textbf{API Configuration Profile}
      dropdown at the top.
   \item Click the \textbf{profile name} field next to the dropdown and type a
      descriptive name (e.g., \rcode{Claude-Agentic}, \rcode{Gemini-Docs},
      \rcode{Ollama-Private}).
   \item Click \textbf{Save as new profile}.
   \item Configure the \textbf{API Provider}, \textbf{Model}, \textbf{API Key},
      and optionally a custom \textbf{Temperature} for this profile.
   \item Click \textbf{Done} to save.
\end{enumerate}

\includegraphics{./include/graphics/roocode/RooCodeProfileCreate.png}

\subsection{Switching Between Profiles}

Once multiple profiles are saved, you can switch between them in two ways:

\begin{itemize}
   \item \textbf{From the Settings panel:}
      Open \textbf{Settings} (gear icon) and select the desired profile from
      the \textbf{Configuration Profile} dropdown in the \textbf{Providers} section.

      \includegraphics{./include/graphics/roocode/RooCodeProfileSwitch_Settings.png}

   \item \textbf{From the Chat panel:}
      A profile selector dropdown is available directly above the chat input,
      allowing instant switching without leaving your current task.

      \includegraphics{./include/graphics/roocode/RooCodeProfileSwitch_Chat.png}

\end{itemize}

\subsection{Assigning a Default Profile per Mode}

Each Roo Code working mode (Code, Architect, Debug, Ask, Orchestrator) can
have its \textbf{own default profile} assigned.
When you switch modes, Roo Code automatically activates the corresponding
profile.

\begin{enumerate}
   \item Open \textbf{Settings} (gear icon).
   \item Navigate to the \textbf{Modes} section.
   \item For each mode, select the desired profile from the
      \textbf{API Configuration} dropdown.
   \item Click \textbf{Done}.
\end{enumerate}

\includegraphics{./include/graphics/roocode/RooCodeProfilePerMode.png}

\begin{boxhint}{Recommended Profile Setup}
\begin{itemize}
   \item \textbf{Code / Debug / Orchestrator modes} → assign your most capable
      model profile (e.g., \rcode{Claude-Agentic}).
      These modes perform complex multi-file edits and autonomous tool use.
   \item \textbf{Architect / Ask modes} → a mid-tier or cheaper model profile
      is usually sufficient, as these modes are read-only or design-focused.
\end{itemize}
\end{boxhint}

\subsection{Profile Settings Overview}

Each profile stores the following settings independently:

\begin{itemize}
   \item \textbf{API Provider:} The LLM service (Anthropic, OpenAI, Google
      Gemini, Ollama, VS Code LM API, etc.).
   \item \textbf{Model:} The specific model variant within the provider
      (e.g., \rcode{claude-sonnet-4-5}, \rcode{gpt-4o}).
   \item \textbf{API Key:} Stored securely per profile — useful when using
      multiple provider accounts.
   \item \textbf{Temperature:} Controls the randomness of the model's output.
      Lower values (0.0-0.3) are recommended for code generation;
      higher values (0.5-0.8) suit design brainstorming or documentation.
   \item \textbf{Context Window / Max Tokens:} Advanced limits that can be
      tuned per profile for cost control.
\end{itemize}

\section{Best Practices for Automation Engineers}
\begin{itemize}
   \item \textbf{Context Management:}
      Keep only relevant files open to reduce token costs.
   \item \textbf{Terminal Verification:}
      Always let Roo Code run your Robot Framework commands
      (e.g., \plog{robot path/to/test.robot}) to verify its own fixes.
   \item \textbf{Approval Workflow:}
      Carefully review the \textbf{Diff} view before clicking \textbf{"Approve"}
      to ensure the accuracy of file changes.
\end{itemize}
